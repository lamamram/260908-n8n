Les gestes et syntaxes du quotidien, en une référence rapide. À garder ouvert pendant les ateliers.

Démarrer une instance locale

# Docker (recommandé en formation)
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -e GENERIC_TIMEZONE="Europe/Paris" -e TZ="Europe/Paris" \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

# npm (poste de développement)
npm install n8n -g
n8n start

# Tunnel de test pour webhooks (développement uniquement !)
n8n start --tunnel

Éditeur : http://localhost:5678.

Le modèle de données en 30 secondes

  • Les données circulent en tableau d'items : [{ "json": {...} }, ...].
  • Un nœud s'exécute une fois par item (sauf réglage Execute Once).
  • Un nœud qui retourne zéro item arrête la branche.
  • binary porte les fichiers ; vérifier l'onglet Binary de la sortie.

Fiabilité : la hiérarchie des défenses

  1. Retry On Fail (Settings du nœud) — pannes transitoires (429, 503).
  2. Continue On Fail + branche d'exception — items fautifs isolés.

  3. Workflow d'erreur (Error Trigger + notification) rattaché dans les Settings du workflow — tout échec définitif signalé.

  4. Stop and Error — incohérences métier remontées avec un message clair.

Contexte reçu par l'Error Trigger :

{
  "execution": { "id": "...", "url": "...", "error": { "message": "..." },
                 "lastNodeExecuted": "...", "mode": "..." },
  "workflow": { "id": "...", "name": "..." }
}

(erreur de déclencheur : objet trigger à la place d'execution).

Checklist avant activation d'un workflow

  1. Aucune épingle sur les nœuds.
  2. Nœuds nommés par des verbes d'action.
  3. Credentials de service (pas personnels), permissions minimales.
  4. Chaque branche testée ; fallback du Switch utilisé.
  5. Retry / exception / workflow d'erreur décidés par nœud à risque.
  6. Aucun secret dans les paramètres ni dans les items.
  7. Sticky note : processus, propriétaire, contraintes.
  8. Sauvegarder, activer, surveiller la première exécution réelle.

Ce glossaire rassemble les termes rencontrés pendant la formation. Le terme français est donné en premier, l'anglais d'usage entre parenthèses.

A

  • API (interface de programmation applicative) : ensemble d'opérations qu'un service expose pour être interrogé ou modifié par un logiciel, via HTTP.

  • Atelier : mise en pratique guidée pendant la formation (voir aussi TP).

  • Auto-hébergement (self-hosting) : faire tourner n8n sur sa propre machine ou son propre serveur plutôt que sur n8n Cloud.

  • Authentification : mécanisme par lequel un système vérifie l'identité de l'appelant (clé d'API, Basic Auth, OAuth2…).

B

  • Batching (traitement par lots) : découpage des appels en paquets espacés pour respecter les quotas d'une API. Voir Loop Over Items.

  • Branche : chemin parallèle d'un workflow, créé par plusieurs connexions sortantes ou par un nœud de logique (IF, Switch).

  • Branche d'exception : chemin qui reçoit les items en échec quand un nœud est en Continue On Fail.

C

  • Canvas (canevas) : la surface de l'éditeur n8n sur laquelle on pose et relie les nœuds.

  • Clé d'API (API key) : chaîne secrète générée par un service pour identifier un appelant ; à stocker dans un credential, jamais en clair.

  • Code (nœud) : nœud qui exécute du JavaScript ou du Python comme étape du flux ; deux modes : une fois pour tous les items, ou une fois par item.

  • Credential (identifiant) : jeu d'accès (clé, compte, jeton) stocké chiffré dans n8n et réutilisable par tous les workflows.

  • Cron (expression) : syntaxe de planification (0 8 * * 1 = chaque lundi à 8 h) utilisée par le déclencheur planifié en mode personnalisé.

D

  • Déclencheur (trigger) : nœud qui met le workflow en marche — manuel, planifié, webhook ou événement d'application.

  • Déclencheur d'application (app trigger) : déclencheur lié à un service précis (Gmail, Slack…), en mode polling ou webhook.

E

  • Épinglage (pin) : figeage de la sortie d'un nœud pour réutiliser ces données aux exécutions de test suivantes, sans rappeler le service amont.

  • Error Trigger : déclencheur spécial qui ouvre un workflow d'erreur et reçoit le contexte de l'échec (workflow, exécution, dernier nœud, message).

  • Exécution : un passage complet d'un workflow, daté, avec les données d'entrée et de sortie de chaque nœud.

  • Expression : formule JavaScript entre doubles accolades {{ }} évaluée pour chaque item dans les paramètres des nœuds.

F

  • Fair-code : modèle de licence de n8n (Sustainable Use License) : code source disponible, usage interne libre, revente comme service restreinte.

  • Fallback Output : sortie de secours d'un nœud Switch pour les items qui ne correspondent à aucune règle.

  • Fil rouge : le workflow construit progressivement tout au long de la formation (routage des demandes).

I

  • Instance : une installation de n8n en fonctionnement (éditeur + moteur + base de données).

  • Intégration native : nœud dédié à un service (Gmail, GitHub…), avec opérations et credential prédéfinis.

  • Item : élément du tableau de données qui circule entre les nœuds ; porte une clé json (données) et éventuellement binary (fichiers).

J

  • JMESPath : langage de requête pour JSON, disponible dans les expressions via $jmespath(), pour extraire des données de structures imbriquées.

  • JSON (JavaScript Object Notation) : format texte de données structurées (objets, tableaux) utilisé par les API et par le modèle d'items de n8n.

L

  • Loop Over Items : nœud de boucle par lots (ancien nom : Split In Batches) ; émet chaque lot par « loop » et signale la fin par « done ».

  • Low-code : construction visuelle d'applications avec possibilité d'injecter du code ponctuellement (position de n8n).

  • Luxon : bibliothèque de dates utilisée par n8n ($now, $today).

M

  • Merge : nœud de fusion de deux flux (Append, jointures par champs correspondants, par position, produit cartésien, SQL).

  • Moindre privilège : principe de n'accorder à une clé ou un compte que les permissions strictement nécessaires au flux prévu.

N

  • n8n Cloud : l'offre hébergée et managée par l'éditeur de n8n.
  • No-code : construction entièrement visuelle, sans écriture de code.
  • Nœud (node) : brique d'un workflow — déclencheur, action, logique ou transformation.

O

  • OAuth2 : protocole de délégation d'accès ; l'utilisateur autorise l'application, le service émet un jeton renouvelable. Flux principaux : Authorization Code, Client Credentials, PKCE.

  • Orchestration : coordination automatisée d'étapes réparties entre plusieurs applications, avec journalisation et gestion d'erreurs.

P

  • Pagination : découpage des réponses volumineuses d'une API en pages ; gérée par l'option du nœud HTTP Request ou par une boucle.

  • Paired item : lien de traçabilité entre un item de sortie et l'item d'entrée dont il descend ; alimente la navigation dans les exécutions.

  • Polling (interrogation) : détection d'événements par appels réguliers au service (« y a-t-il du nouveau ? »), par opposition au webhook (push).

  • Projet (project) : espace de regroupement de workflows et credentials avec gestion des droits (selon édition).

Q

  • Queue mode (mode file d'attente) : architecture de montée en charge : instance principale + Redis (file) + workers d'exécution + PostgreSQL.

R

  • Rate limiting (quota d'API) : limitation du nombre de requêtes par un service ; réponse typique 429 Too Many Requests.

  • Respond to Webhook : nœud qui compose la réponse HTTP renvoyée à l'appelant d'un webhook.

  • Reverse proxy : serveur frontal (Traefik, nginx) qui termine TLS et redirige vers n8n sans exposer son port.

  • Retry On Fail : réglage de nœud qui réessaie automatiquement après un échec (nombre de tentatives et intervalle).

S

  • Scope : permission précise accordée à un jeton OAuth2 ou une clé d'API.

  • SSRF : attaque qui détourne un serveur pour appeler des ressources internes ; n8n propose une protection dédiée à activer.

  • Sticky note : note autocollante libre posée sur le canevas pour documenter le flux.

  • Stop and Error : nœud qui fait échouer volontairement l'exécution avec un message explicite, remonté au workflow d'erreur.

  • Sous-workflow : workflow appelé par un autre via le nœud Execute Workflow, pour réutiliser ou découper la logique.

T

  • TP (Travaux Pratiques) : voir Atelier.
  • Tunnel : URL publique temporaire fournie par n8n start --tunnel pour tester les webhooks en développement — jamais en production.

V

  • Variable d'environnement : réglage de l'instance lu au démarrage (fuseau horaire, base de données, clé de chiffrement…), défini dans le fichier .env ou le compose.

  • Volume (Docker) : espace de stockage persistant monté dans le conteneur ; n8n_data conserve workflows, credentials et base entre les redémarrages.

W

  • Webhook : URL HTTP exposée par n8n qu'un service externe appelle pour déclencher un flux ; existe en version de test et de production.

  • Workflow : le flux d'automatisation dessiné sur le canevas — déclencheur, nœuds, connexions ; actif ou inactif.

  • Workflow d'erreur : workflow dédié (commençant par Error Trigger) exécuté à chaque échec d'un workflow auquel il est rattaché.

  • Worker : processus n8n qui exécute les workflows en queue mode, en parallèle de l'instance principale.
